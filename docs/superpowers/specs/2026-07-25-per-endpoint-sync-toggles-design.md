# Per-endpoint / global sync toggles for Network / Sensors / Event Log / Manager Health

## Background

`netbox_bmc` runs four independent background sync systems (Network, Sensors, Event Log,
Manager Health), each with: a per-endpoint "Sync X" button + `*SyncJob`, a scheduled
bulk job (`Scheduled*SyncJob`) gated by a `*_sync_interval_minutes` plugin setting, and a
card on the `BMCEndpoint` detail page showing the synced data.

Some sites don't need every sync type on every device (e.g. a GPU host operator may not
care about Event Log at all, or a whole fleet may never need Manager Health). Today the
only way to stop a sync type is to set its `*_sync_interval_minutes` to 0, which disables
the *scheduled* job for *all* endpoints — there's no way to opt individual endpoints out,
and no way to fully suppress a sync type (manual button still works, card still shows).

## Goals

- A per-`BMCEndpoint` checkbox for each of the 4 sync types (Network / Sensors / Event
  Log / Manager Health), defaulting to enabled (matches current behavior).
- A global master switch per sync type, set via `PLUGINS_CONFIG["netbox_bmc"]`, that
  overrides the per-endpoint checkbox when `False` (disables that sync type everywhere,
  regardless of what any endpoint's checkbox says).
- When a sync type is disabled (globally or per-endpoint): the scheduled bulk job skips
  it, the manual "Sync X" button/view refuses it, and the corresponding card is hidden
  from the `BMCEndpoint` detail page.

## Non-goals

- Inventory / Module sync (`BuildModulesView`, `ScheduledInventorySyncJob`) is untouched
  — this only covers the 4 `*SyncJob` systems described above.
- No REST API changes beyond the 4 new model fields being included automatically in the
  existing `BMCEndpoint` serializer.
- No changes to `credentials.py` or the netbox-secrets integration.

## Design

### Model (`models.py`)

Add 4 `BooleanField`s to `BMCEndpoint`, same style as the existing `use_netbox_secrets`
field, each `default=True`:

```python
network_sync_enabled = models.BooleanField(default=True)
sensors_sync_enabled = models.BooleanField(default=True)
event_log_sync_enabled = models.BooleanField(default=True)
manager_health_sync_enabled = models.BooleanField(default=True)
```

One migration, hand-written + verified with
`manage.py makemigrations netbox_bmc --check --dry-run` per this repo's convention
(migrations can't be autogenerated inside the netbox-docker container).

### Effective-enabled helper (`jobs.py`)

A single small helper computes the effective enabled state, combining the plugin-wide
master switch and the per-endpoint checkbox:

```python
def _sync_enabled(kind: str, endpoint) -> bool:
    """kind: 'network' | 'sensors' | 'event_log' | 'manager_health'"""
    plugin_cfg = settings.PLUGINS_CONFIG.get("netbox_bmc", {})
    if not plugin_cfg.get(f"{kind}_sync_enabled", True):
        return False
    return getattr(endpoint, f"{kind}_sync_enabled")
```

Used in 3 places per sync type (12 call sites total, 4 kinds x 3 places):

1. **`Scheduled*SyncJob.run()`**: instead of `BMCEndpoint.objects.all()`, filter with a
   Python-level `[e for e in BMCEndpoint.objects.all() if _sync_enabled(kind, e)]` (the
   plugin-wide part can't be expressed as a DB filter since it's not a model field, so no
   point special-casing the per-endpoint part as a `.filter()` — keep it one simple list
   comprehension). If the plugin-wide switch is off, this naturally skips every endpoint;
   `self.job.data` message should say `"Synced N/M endpoint(s) (sync disabled globally)"`
   when the switch is off, or `"...  (K disabled)"` when only some endpoints are opted
   out, so it's clear from the job log why the count looks low.
2. **`*SyncActionView.post()`** (`views.py`, e.g. `NetworkSyncActionView`,
   `ManagerHealthSyncActionView`, `SensorsSyncActionView`, `EventLogSyncActionView`):
   before enqueueing, check `_sync_enabled(kind, endpoint)`; if `False`,
   `messages.error(request, _("... sync is disabled for this endpoint."))` and redirect
   without enqueueing.
3. **`bmcendpoint.html` template**: each of the 4 `<div class="card">` blocks (Network at
   line ~22, Manager Health at ~237, Sensors at ~276, Event Log at ~321) wrapped in
   `{% if object.network_sync_enabled and network_sync_globally_enabled %}` — the
   "globally enabled" half needs to reach the template via the view context (see below),
   since templates can't read `settings.PLUGINS_CONFIG` directly without a custom
   templatetag.

### View context (`views.py`, `BMCEndpointView` or equivalent detail view)

Add the 4 plugin-wide flags to the detail view's `get_extra_context()` (or equivalent),
e.g.:

```python
plugin_cfg = settings.PLUGINS_CONFIG.get("netbox_bmc", {})
context["sync_flags"] = {
    kind: plugin_cfg.get(f"{kind}_sync_enabled", True)
    for kind in ("network", "sensors", "event_log", "manager_health")
}
```

Template condition becomes `{% if object.network_sync_enabled and sync_flags.network %}`.

### Form (`forms.py`)

Add a new `FieldSet("network_sync_enabled", "sensors_sync_enabled",
"event_log_sync_enabled", "manager_health_sync_enabled", name=_("Sync Options"))` and add
the 4 fields to `Meta.fields`.

Mirroring the existing `use_netbox_secrets` pattern (hidden from the form when
netbox-secrets isn't installed), in `__init__` remove any of the 4 checkbox fields from
the form (and drop them from the "Sync Options" `FieldSet`) when the corresponding
plugin-wide switch is `False` — the checkbox is moot if the sync type is killed globally.
If all 4 end up disabled, drop the whole `FieldSet`.

### Plugin config (`configuration/plugins.py`, deployment-side, not part of this repo's
code change but documented in `CLAUDE.md`'s plugin settings table)

New optional keys, default `True` when absent:

```python
"netbox_bmc": {
    ...
    "network_sync_enabled": True,
    "sensors_sync_enabled": True,
    "event_log_sync_enabled": True,
    "manager_health_sync_enabled": True,
}
```

## Testing

- `jobs.py` (like `views.py` and `models.py`) imports `django.utils.timezone` and isn't
  importable under this repo's Django-free `tests/` suite (see `CLAUDE.md`), so
  `_sync_enabled()` is verified the same way the rest of `jobs.py` already is: manually
  against `netbox-dev.test1`, not via `uv run pytest`. No new pytest coverage is added
  for this change.
- Manual verification on `netbox-dev.test1`: uncheck Event Log for one endpoint, confirm
  its card disappears, confirm `EventLogSyncActionView` POST (curl) is refused, confirm
  `ScheduledEventLogSyncJob` skips it while still syncing other endpoints. Then set
  `event_log_sync_enabled: False` in `PLUGINS_CONFIG` and confirm the checkbox disappears
  from the form and every endpoint's Event Log card disappears regardless of its stored
  per-endpoint value.
